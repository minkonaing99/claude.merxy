Why signatures exist★★

Key terms

Integrity
The message arrived exactly as sent.
Authenticity
The message really came from the claimed sender.
Non-repudiation
The sender cannot later deny sending it.

Encryption hides a message. It does not tell Bob who sent it. Anyone with Bob's public key can encrypt a note and sign it "Alice". slide 3

A signature solves the opposite problem. The message can be public; what matters is proof that only Alice could have produced it. Think of a wax seal: anyone can read the letter, but only the owner of the ring can press that seal. slide 4

Rule. Encryption uses the receiver's public key. Signing uses the sender's private key.

a signature is something only Alice can make and anyone can check.

Sign and verify★★★

Key terms

H(m)
The hash of message m: a short fixed-size fingerprint.
d
Alice's private exponent. Only she knows it.
(e, n)
Alice's public key. Everyone knows it.
s
The signature, a number sent alongside the message.

Alice hashes the message, then raises the hash to her private exponent. Bob raises the signature to Alice's public exponent and checks that he gets the same hash back. slide 7

Sign:   s = H(m)^d mod n
Verify: H(m) =? s^e mod n

Derive, don't memorize

Remember only the sign line. Verify falls out because e and d undo each other: (H^d)^e = H^(de) = H mod n, since de = 1 mod φ(n). slide 8

Common trap. Signing with the receiver's key, or verifying with the private key. The private key never leaves Alice. slide 9

Alice locks the fingerprint with a key only she has; anyone can unlock it with her public key and see if the fingerprint matches.

Worked example★★★

Tiny numbers so you can do it by hand. Real keys are 2048 bits or more. own example, based on slide 7

own example, based on slide 7
ValueNumberWhere it comes from

φ(n)40(5-1)(11-1)
e3public, shares no factor with 40
d273 x 27 = 81 = 2 x 40 + 1
H(m)7pretend hash of the message
  1. Alice signs: s = 7^27 mod 55 = 28.
  2. She sends the message and s = 28.
  3. Bob computes 28^3 mod 55 = 21952 mod 55 = 7.
  4. Bob hashes the message himself and also gets 7. They match: valid.
What goes wrong. If an attacker changes the message so its hash becomes 8, Bob still computes 28^3 mod 55 = 7. Since 7 is not 8, the signature fails and the change is caught.

Your turn

Same keys (n = 55, e = 3, d = 27). Each example leaves more for you. own example, based on slide 7

One gap

  1. H(m) = 9, so s = 9^27 mod 55 = 4.
  2. Bob computes 4^3 mod 55 = ?

64 mod 55 = 9. Matches the hash, so the signature is valid.

Two gaps

  1. H(m) = 12, so s = 12^27 mod 55 = ?
  2. Bob's check: s^3 mod 55 = ?

s = 23. Then 23^3 = 12167, and 12167 mod 55 = 12. Valid.

On your own

Someone sends H(m) = 7 with signature s = 13. Is it valid?

13^3 = 2197, and 2197 mod 55 = 52. Since 52 is not 7, reject it.
